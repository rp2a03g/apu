# Mesen 2 用: ゲームを遊びながらサウンドレジスタを VGM に録音する

`vgm-recorder.lua` は Mesen 2 の Lua スクリプト。ゲームをプレイしている最中の
サウンドレジスタ書き込み(効果音・処理落ち込み)を VGM ファイルに記録する。
できた .vgm は Sound Emulation Foundry の「ファイルを開く」でそのまま読め、
再生・ピアノロール・MML 変換まで通常の VGM として扱われる。

対応機種(Mesen が動かせるもの):

| 機種 | VGM のチップ | 備考 |
|---|---|---|
| NES / ファミコン | NES APU(+FDS) | 拡張音源(VRC6/VRC7/MMC5/N163/SUNSOFT 5B)は本ツール専用ブロックで同梱 |
| ゲームボーイ / GBC | GB DMG | 波形 RAM 込み |
| PC エンジン | HuC6280 | 波形 RAM 込み |
| マスターシステム / ゲームギア | SN76489 | GG のステレオ(ポート $06)も記録 |

NSF と違って曲を切り出す必要がなく、ROM さえあればよい。先頭は録音開始地点。
「曲に合わせて効果音を鳴らす」「ジングルを割り込ませる」といったゲームを使った演奏を
そのまま残す用途。曲だけが欲しいときは、本ツールの変換設定「録音の補正」で効果音を除く(曲が
3 周以上入るように録る。周回の多数決で効果音だけ落ちる)・処理落ちを詰める、を選べる(既定は OFF)。Mesen が直接読める `.nsf` / `.gbs` / `.hes` を開いて走らせれば、
そのドライバの出力も同じ形で録れる(変換結果の照合に使える)。

メガドライブと MSX は Mesen が対応していないので、BlastEm / openMSX の VGM 録音機能で
作ったファイルをそのまま本ツールで開く(本ツールは VGM を読むだけで録ったエミュレータを問わない)。

## 使い方

1. Mesen 2 → 設定 → Script Window → **Allow access to I/O and OS functions** を ON
   (ファイル書き出しに要る。ON でないとスクリプトログにエラーが出て何も書けない)。
2. Debug → Script Window でこのファイルを開いて Run。ゲームを始める前に走らせておく
   (録音開始時点のレジスタ状態を復元するため。リセット後にスクリプトを自動再開する設定なら
   そのままでよい)。機種は自動判定(スクリプトログに `ready (gb, …)` のように出る)。
3. 録音したい所で **F9**(録音開始)。もう一度 F9 で停止。画面左上に REC とフレーム数が出る。
4. 出力先は Mesen のスクリプト用データフォルダ
   (`<Mesen のホーム>/LuaScriptData/vgm-recorder/<ROM名>_<日時>.vgm`)。
   フルパスはスクリプトログに出る。

## 設定(ファイル冒頭の CFG)

| 項目 | 既定 | 意味 |
|---|---|---|
| `autoStart` | false | true ならスクリプト開始と同時に録音開始 |
| `toggleKey` | "F9" | 録音の開始/停止キー |
| `outDir` | nil | 出力フォルダ(nil ならスクリプト用データフォルダ) |
| `preciseTiming` | false | 各書き込みにフレーム内の時刻を付ける。$4011 直書き PCM を鳴らす曲向け。書き込みごとに `emu.getState()` を呼ぶので重い(headless 計測で約2割増。PCM を毎フレーム数百回書く曲では追いつかない可能性) |
| `stopAfterFrames` | 0 | >0 ならそのフレーム数で停止して `emu.stop()`(headless テスト用) |
| `flushEvery` | 60 | このフレームごとに flush しヘッダを書き直す。途中で落ちても直前までは読める |
| `console` | nil | 機種の強制("nes" "gb" "pce" "sms" "gg")。nil なら `emu.getState().consoleType` と拡張子で判定 |
| `mapper` | nil | NES: マッパー番号の強制(ROM の iNES ヘッダが読めない時用) |
| `pcePsgBase` | 0x0800 | PCE: PSG レジスタの論理アドレス(ハードウェアページを $0000 に置く慣例 MPR0=$FF のとき $0800) |

## 記録の仕組みと制約(機種共通)

- 1 フレーム = VGM の 735 サンプル(1/60 秒)固定。実機のフレームレート(NES 60.0988Hz、
  GB 59.73Hz、PCE 59.8Hz、SMS 59.92Hz)に関係なく、本ツールは 735 サンプル=1 フレームで区切るので
  フレームが 1 つもずれず、MML 変換はネイティブ形式の直接変換と同じ譜面になる
  (`tools/headless/nsf2vgm.js` で NSF から同じ符号化の VGM を作り、2A03+DPCM の曲で
  変換結果が完全一致することを確認済み。GBS/HES は Mesen で直接開いて録音したものと
  直接変換の旋律が一致。エンベロープの @v 番号と先頭の休符は数フレームぶん違う)。
  処理落ちしたフレームは書き込みの無いフレームとして残る。
- 録音開始時のレジスタ状態: スクリプト開始後の書き込みを影レジスタに控え、録音開始時に
  フレーム 0 の頭へまとめて書く(音を出すイネーブルを最後に)。スクリプトより前に書かれた値は
  分からない。
- GD3: track=録音日時、game=ROM 名、system=機種名。

### NES

- DPCM: `$4015` の bit4 を立てる書き込みの直前に、`$4012/$4013` が指すサンプル本体を
  CPU 空間から読んで VGM データブロック(0x67 type 0xC2)に入れる。同じ場所・同じ内容なら
  2 回目以降は省く。本ツールの変換はトリガー時点の RAM 像でサンプルを解決する。
- 初期状態で `$4015` の DPCM 鳴りかけは復元しない。FDS の変調テーブル(`$4088`)も復元しない。
  スクリプトより前の値が無いときは `$4015=$0F` だけ補う。
- 拡張音源(VRC6/VRC7/N163/MMC5/SUNSOFT 5B): VGM の規格に無いので、本ツール専用のデータブロック
  (0x67 type 0xBF、先頭 "NESX"、設計は DESIGN-CAPTURE.md §3.3)で運ぶ。標準プレイヤーは未知の型として
  読み飛ばすので 2A03+FDS だけが鳴り、本ツールは拡張音源込みで再生・変換する。どのチップかは ROM ファイルの
  iNES ヘッダのマッパー番号で決める(24/26=VRC6、85=VRC7、19=N163、5=MMC5、69=SUNSOFT 5B。
  `CFG.mapper` で強制もできる)。マッパー 26(VRC6b)はアドレス線を入れ替えて NSF の慣例(VRC6a)に正規化する。
  N163 は $4800 の読み出しでもポインタが進むので読み出しも記録する。

### ゲームボーイ

- `$FF10-$FF3F` → `0xB3`(波形 RAM は 0x20-0x2F)。
- 初期状態の復元は NR52 電源 → NR50/NR51 → ch3 DAC off → 波形 RAM → 各 ch の順。NRx4 のトリガ(bit7)は
  落とすので、録音開始時に鳴っていた音は次のキーオンまで鳴らない(長さカウンタ等は復元できないため)。

### PC エンジン

- PSG(`$0800-$0809`)→ `0xB9`。ハードウェアページが論理 `$0000` にある前提(MPR0=$FF、ほぼ全ソフトの慣例)。
  別の場所に置くソフトは `CFG.pcePsgBase` で合わせる。
- 波形 RAM は「ch が止まっている間の `$0806` 書き込み」を 32 バイトの影に写す。初期状態の復元では
  DDA を立てて戻してポインタを 0 にしてから 32 回書くので、鳴っていた ch の位相は 0 に戻る。

### マスターシステム / ゲームギア

- ポート `$40-$7F` → `0x50`、GG のステレオ(ポート `$06`)→ `0x4F`。GG かどうかは拡張子 `.gg` で決める。
- Mesen 2(2.2.1 で実測)はポート書き込みのコールバックを `smsPort` 型では鳴らさず、ポート番号を CPU アドレスと
  みなした絶対アドレス(ROM 先頭 256 バイト=`smsPrgRom` 型)に当ててくる。両方の型で登録しているので
  どちらの挙動でも録れるが、ROM の `$0040-$007F` へ書き込むソフトがあれば誤検出になる(実用上は無い)。
- 日本版 SMS の FM(YM2413)は未対応。

## ライブ表示(録音せずにロールを見る)

本体の鍵盤表示ヘッダ [LIVE] は、外から WebSocket(既定 `ws://localhost:8765`)で届く書き込みを
ロールへ追記する(未来が無いので、鳴った音符が鍵盤の縁から生えて遠ざかる)。メッセージ形式は
`src/ui/liveRoll.js` 冒頭。Mesen の Lua から直接ソケットへ流せるかは未確認なので、見本の中継
`tools/live/vgm-ws-relay.js`(録音した VGM を実時間で流す)で形式と表示を確かめられる:

```
node tools/live/vgm-ws-relay.js rec.vgm --loop
```

## 自前 NES エミュレータの基準画面(ref-screenshot.lua)

`ref-screenshot.lua` は「決まったフレームにボタンを押し、決まったフレームで画面を PNG に保存」する
(冒頭の CFG を書き換える)。`tools/headless/nes-run.js` の `--press` と同じ指定で同じフレームの画面を
作り、自前エミュレータ(src/emulator/nes/)の画面と見比べる:

```
Mesen.exe --testRunner "game.nes" "tools/mesen/ref-screenshot.lua" --timeout=120
node tools/headless/nes-run.js "game.nes" --frames 1301 --press "start:700-710,right:900-1300" --png mine.png
```

パレットは Mesen と本ツール(nesdev の 2C02 表)で違うので、色ではなく形で比べる。

## headless テスト(GUI 無し・最高速)

```
Mesen.exe --testRunner "rom" "rec.lua" --timeout=60
```

`autoStart=true`, `stopAfterFrames=<n>` にしたコピーを渡すと n フレーム録音して終了する。
rom には `.nes` のほか `.gbs` / `.hes` / `.sms` / `.gg` / `.gb` / `.pce` も渡せる。
headless では `emu.isKeyPressed` がキー名を解決できず例外になるので、スクリプトは pcall で
包んでキー監視を自動で切る(コールバック内の例外は Mesen がログに出すだけでスクリプトは
止まらない。放っておくと毎フレーム例外で wait もヘッダ更新も飛ぶ)。
