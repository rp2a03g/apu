# Sound Emulation Foundry - ppmckc ed.

ブラウザ上で動作するファミコン(RP2A03)＋拡張音源対応MML制作環境。
MMLコンパイラ・6502アセンブラ・NSFジェネレーター・音源エミュレータをすべてJavaScriptで内製する。

> **開発に着手する前に必ず読むこと:**
> - [DESIGN.md](DESIGN.md) — 恒久的な設計原則(不変条件 INV-1〜6、Song IR仕様、層の分離ルール)
> - [ROADMAP.md](ROADMAP.md) — 実装フェーズと各タスクの受け入れ条件

## 現在の状態: Phase 1 + Phase 2 + Phase 3 + Phase 4 + Phase 5 + Phase 6

### Phase 1: 6502アセンブラ & NSFジェネレーター

- `src/asm/opcodes.js` — 6502 命令セット（合法151オペコード）の定義
- `src/asm/assembler.js` — 2パス方式の簡易6502アセンブラ
  - ラベル、各種アドレッシングモード、`.org` `.byte`/`.db` `.word`/`.dw` `.res`/`.ds` ディレクティブに対応
- `src/nsf/nsfHeader.js` — NSF 128バイトヘッダの生成・解析
- `src/nsf/nsfBuilder.js` — ヘッダ＋プログラムイメージからNSFバイナリを生成、ダウンロード

### Phase 2: NSF対応エミュレータ（6502 CPU + 2A03音源）

- `src/emulator/cpu6502.js` — 6502 CPUコア（全151オペコード、`call()`でINIT/PLAYサブルーチン実行）
- `src/emulator/apu2a03.js` — 2A03 APU（パルスx2・三角波・ノイズ・DMCの4ch合成、NES非線形ミキサー実装）
- `src/emulator/nsfBus.js` — NSF実行用メモリバス（$4000-$4017をAPUへルーティング、バンクスイッチ対応）
- `src/emulator/nsfPlayer.js` — INIT/PLAY呼び出し + フレーム単位の音声サンプル生成
- `src/driver/sampleDriver.js` — 約440Hzのトーンを鳴らすパルス1チャンネルの最小ドライバ
- `index.html` / `src/main.js` — アセンブル結果・NSFヘッダプレビュー・ダウンロード・「▶試聴」によるエミュレータ再生UI

### Phase 3: 再生ログ一括キャプチャ & シーク/早送り/巻き戻し

- `src/emulator/capture.js`
  - `MML.Emu.captureSong(nsfBytes, opt)` — INIT実行後、指定秒数分のPLAYルーチンを毎フレーム実行し、全フレームの音声波形（DCブロック済み）とレジスタ書き込みタイムラインログを一括生成
  - `MML.Emu.dcBlock(samples)` — APU出力のDCオフセットを除去するワンポールDCブロッカー
- `index.html` / `src/main.js`
  - 「再生・シーク（一括キャプチャ）」パネルを追加（キャプチャ長さ指定、キャプチャ実行ボタン）
  - キャプチャ結果を `AudioBuffer` 化し、`AudioBufferSourceNode.start(0, offset)` による即時シークを実現
  - 再生・一時停止・停止・巻き戻し(-5秒)・早送り(+5秒)・シークバーによるトランスポートUIを実装

### Phase 4: MMLコンパイラ（ppmck互換 基本コマンド）

- `src/mml/lexer.js` — ソースをチャンネル(A-D)別のコマンド文字列に分割し、トークン化
- `src/mml/compiler.js` — `MML.Mml.compile(source)`
  - 対応コマンド: `cdefgab`（音符, `+`/`#`/`-`で半音, 数値で音長, `.`で付点）, `r`（休符）, `n<num>[,<len>]`（直接音程指定,オクターブ2のCを0とした通し番号）, `o` `>` `<`（オクターブ）, `l`（デフォルト音長）, `v`（音量0-15。FDSとVRC6のこぎり波だけは本家ppmck同様0-63のレジスタ生値で、FDSは実効32で頭打ち・VRC6サウは実質42が最大＝43以上は実機の8bit桁溢れで鋸波が崩れるだけで音量は上がらない。`@v`/`@vr`のテーブル値も同じ範囲）, `v+` `v-`（音量相対増減,省略時±1）, `q`（ゲートタイム0-8）, `@q<n>`（フレーム単位の早期ノートオフ）, `t`（テンポ、曲中の任意位置で変更可）, `K<n>`（移調・半音）, `@`（音色=デューティ比）, `&`（タイ）, `[ ]n`（繰り返し）, `[ ... | ... ]n`（最後の周回だけ`|`以降を演奏しない）, `{ ... }<len>`（連符・等分）, `EN<n>`/`ENOF`+`@EN<n>={...}`（ノートエンベロープ=高速アルペジオ、2A03全ch+全拡張音源(VRC7含む)対応、仕様通り厳密実装）, `EP<n>[,<delay>]`/`EPOF`+`@EP<n>={...}`（ピッチエンベロープ、2A03全ch+VRC6/MMC5/FME7/FDS/N163対応(VRC7はfnum/blockの対数表現のため対象外)、実機`sound_pitch_enverope`と同一の生レジスタオフセット空間で厳密実装。`,<delay>`は**ppmck本家仕様には無いこのツール独自の拡張**＝発動を`<delay>`フレーム遅らせてから0番地からテーブルを辿る。省略時delay=0で従来通り）, `MP<n>`/`MPOF`+`@MP<n>={delay,speed,depth}`（ビブラート、対応範囲はEPと同じ、実機`lfo_sub`/`warizan_start`を忠実移植した厳密実装。滑らかな三角波ではなく実機通りの階段状の変化になる）, `PT<target>,<duration>[,<delay>]`/`PTOF`（ポルタメント=単調な直線グライド、対応範囲はEPと同じ。**ppmck本家ドキュメント（doc/mck.txt）には専用コマンドが無く「ピッチエンベロープ(EP)で代用してください」と明記されているため、これはppmck方言からの独自拡張**。targetはD<n>/EP<n>と同じ生レジスタオフセット空間、durationフレームで0からtargetへ到達し以降は最終値を保持。内部アルゴリズムはMPの`warizan_start`片道版(反転無し)と同一で6502ドライバ側もCEILDIVを共有）, `s<speed>,<depth>`（スイープ、対応範囲はEPと同じ、実機の生ハードウェアスイープレジスタ書き込みを厳密実装）
  - `@t<len>,<num>`（テンポ2、フレーム単位。`<len>`の音符が確実に`<num>`フレームになる非整数テンポを内部で逆算し、`t<n>`の整数BPM丸めによるフレーム端数化を避ける）, `w<len>`（ウェイト、直前のコマンド=音符/休符/wを音長ぶんそのまま延長。タイと同じ仕組み）, `y<adr>,<num>`（レジスタ直接書き込み、`$`接頭辞の16進アドレス対応。ブラウザ再生でも該当アドレスへそのまま書き込む）, `x<param0>,<param1>`（データストリームへのバイト直接埋め込み。**NSF書き出し=6502バイトコード専用のコマンドで、ブラウザ再生には対応する概念が無いためパースのみ行い無視する**）
  - `SD<n>`/`SDOF`/`SDQR`（セルフディレイ=疑似エコー。リリースエンベロープが発動する区間のピッチを`<n>`個前のノートオンへ差し替え、実機同様その位置で打ち直す。SDQRはノートオン履歴のリセット。ppmck公式リファレンスの出力例と完全一致することを実測確認済み）。**発動には`@vr<n>`（リリースエンベロープ）と`q<n>`（n<8、ゲートを切ってリリース区間を作る）の両方が必要**で、既定の`q8`ではリリース区間自体が存在しないため何も起きない（実機ppmckも同じ）。`<n>`は0〜8（実機`SELF_DELAY_MAX`）、`SD255`は`SDOF`と同義、三角波とDPCMチャンネルでは使用不可（いずれも実機ppmckcの`datamake.c`に準拠）
  - `@<n>={...}` + `@@<n>`（デューティ=音色エンベロープ。`@v<n>`の音色版で、`{ }`内は0-7の値の列、`|`でループ位置を指定できる。1フレーム1ステップでデューティ比が変化する）。対応はデューティ比を持つチップ（2A03パルスA/B・VRC6パルス・MMC5パルス）。波形/音色番号を持つチップ（FDS・N163・VRC7）では`@<n>`と同じ音色（波形）選択として働き、VRC7のみ`@@<64+n>`=`OP<n>`（`@OP<n>`のユーザー音色をロード+音色番号0）の別名も使える。三角波・ノイズ・DPCM・FME7・VRC6のこぎり波では使用不可（実機ppmckcの対応トラックマスク準拠）。実機同様、`@<n>`を書くとデューティエンベロープは解除される
  - `@@r<n>`（リリース音色、255=OFF。`@vr`の音色版で、ゲートオフの瞬間に音色を`<n>`へ差し替える。デューティ系チップではデューティエンベロープ番号、FDS/VRC7では波形/音色番号として解釈される）。**N163のみ未対応**（波形の共有RAM配置が音符単位のため。書くとコンパイルエラーで通知する）
  - `@vr<n>`（リリースエンベロープ。ゲートオフ=`q<n>`(n<8)や`@q<n>`で音が切れた瞬間から`<n>`番のテーブルで音量を推移させる）。`@v<n>`（ソフトウェア音量エンベロープ）の有無に関わらず発動し、`v<n>`固定音量の音符でもリリースが鳴る（実機ppmckの`putReleaseEffect`が`@v`の有無を条件にしていないのに合わせた仕様）。テーブルは本ツール独自の`@vr<n>={...}`定義を優先し、無ければ**本家同様に`@v<n>`定義を参照する**（`@v1={...}`を定義して`@vr1`で呼ぶ本家のMMLがそのまま通る）
  - `SM`/`SMOF`（スムース、対応範囲はEPと同じ(VRC7除く)。上位バイト=周期/周波数レジスタの位相リセットを伴う書き込みを「値が変化した時だけ」に切り替え、同オクターブ内のレガートでクリック音が出るのを防ぐだけの機能で、ピッチ自体はグライドしない。実機`CMD_SMOOTH`/`EFF2_SMOOTH_ENABLE`を実測確認）
  - `PS`（ポルタメント、対応範囲はEPと同じ(VRC7除く)。`c PS g`のように次の音符そのものをグライド先として使う。実機`process_ps`/`pitchshift_setup`のb_div方式ステップ計算を移植した独自実装で、既存の`PT<target>,<duration>`（明示的な生レジスタオフセット指定）とは別物・共存する。★実機は最初の1サイクルだけ間隔にstepでなくdurationそのものを使うためグライドが次の音符へ食い込むことがある独特の挙動があるが、本実装は音符の時間内で目標へ収束する分かりやすい近似を採用している=ppmck公式リファレンスが明記する「PSコマンド後の音程は正確ではない」という注記の対象範囲を意図的に簡略化）
  - `!`（データスキップ。この記号以降、そのチャンネルのMMLは一切コンパイルされない=以降無音）, `!!`（タイムシフト=再生開始位置。シークバーの開始ハンドルと連動）, `!!!`（**ppmck本家には無いこのツール独自の拡張**＝再生終了位置。シークバーの終了ハンドルと連動、省略時は曲の最後まで）。`compile()`の戻り値`startMarkerFrame`/`endMarkerFrame`で参照できる
  - `@OP<n>={8バイト,$XX可}` / `@OT<n>={TL,FB,...}`（VRC7カスタム音色。8バイト生形式とMGSDRV互換形式の両方に対応、内部的には同じ音色テーブルに統合）, `@FM<n>={64値}`（FDS波形メモリ）, `@N<n>={buf,...}`（N163波形、4の倍数の可変長へ`src/mml/n163Alloc.js`の共有バッファアロケータで格納。複数の異なる波形を同時に確保できる）, `@MW<n>={32値}`+`@MH<n>={delay,freq,depth,waveform}`+`MH<n>`/`MHOF`（FDSピッチ変調。`@MW`には変調カウンタへの増減量そのものを書き、使える値は`0`(維持)/`1`/`2`/`4`/`-1`/`-2`/`-4`/`R`(カウンタを0にリセット)の8種類だけ＝実機の3bitテーブルコードへの読み替えは不要で、それ以外の値はコンパイルエラーになる）, `S<n>`/`M<n>`/`N<n>`（FME7ハードウェアエンベロープ形状/周期・ノイズ周波数、実機PSGレジスタ仕様通り厳密実装）
  - VRC7/FDSは「音色・波形スロットが1系統のみで全ch共有」という実機の制約はあるが、**曲中の動的な切り替えに対応**: VRC7は`OP<n>`コマンド（出現位置で即座にカスタム音色を再ロード）、FDSは`@<n>`（音色番号指定コマンド）で選択中の`@FM<n>`が変わるたびに自動的に波形を再ロードする。N163は`src/mml/n163Alloc.js`の共有バッファアロケータにより、複数の異なる波形を128byte内蔵RAM上の別領域へ同時に確保できる（VRC7/FDSのような単一スロット共有ではない）
  - 複数行にまたがる`{ ... }`定義ブロック（コメント入り可）に対応
  - `#TITLE`/`#COMPOSER`/`#MAKER`/`#PROGRAMER`（メタ情報、`compile()`戻り値の`meta`に格納。`#TITLE`/`#COMPOSER`/`#MAKER`はNSF書き出し時にヘッダのsongName/artist/copyrightへ反映される。`#PROGRAMER`に対応するNSFヘッダ項目は無く未使用）, `#OCTAVE-REV`（`>``<`反転）, `#GATE-DENOM`（`q<n>`のゲート分母変更）, `#EX-VRC6`等（拡張音源宣言、UIのチェックボックスと統合されMML本文だけで有効化できる）, `#AUTO-BANKSWITCH`等バンキング系・`#INCLUDE`（未対応・認識のみで無視）, `$<char> <mml>`（マクロ定義、1回だけの非再帰展開）
  - `@DPCM<n>={"file",freq,size,dac,mode}`（DMCサンプル定義）はパース済み。1個でも定義があると"E"チャンネル(DPCM)が自動的に有効になり（`#EX-*`宣言不要）、実際の再生チャンネル配線（`@<n>`でのサンプル選択→音符の音高がDMCレート表への最近傍量子化で音高付きトリガー）も実装済み。ファイル選択UI（MML内の`@DPCM`参照を自動検出しファイル選択欄を生成）も実装済みで、`compile()`の`opt.dpcmSamples[filename]=Uint8Array`にブラウザで読み込んだ変換済みバイト列を渡すと実際に鳴る
  - **MML→NSF書き出し（バンク切り替え・拡張音源対応）**: 「MML作曲」パネルの「NSF書き出し」ボタンで、実際に再生可能な`.nsf`ファイルをダウンロードできる。MMLはppmck方式のコンパクトなバイトコード（音符1個が基本2〜3バイト、`src/nsf/mckBytecode.js`）にシリアライズされ、専用の6502ドライバ（`src/driver/ppmckDriver.js`、実機ppmckの設計を参考に新規実装）が解釈・再生する。NSFバンク切り替え（`$5FF8`-`$5FFF`、4KB窓×8）に対応しており、1チャンネルが4KBを超える曲データも複数バンクにまたがって正しく再生できる。2A03(A-D)に加えVRC6・MMC5・FME7・FDS・N163・VRC7の全拡張音源に対応（`MML.Mml.compile()`の正解データと突き合わせて実測確認済み）。**使用しているチップのハンドラ・波形/周期テーブルのみを条件付きで固定領域に埋め込む**設計のため、2A03のみの曲では未使用チップのデータは一切含まれない（固定領域実測: 2A03のみ5160B、全6チップ使用でも8431B）。FDS `@FM`・N163 `@N`・VRC7 `@OP`/`@OT`+`OP<n>`のカスタム波形・音色も、実際に定義されている場合のみテーブル・再ロード処理を条件付きで埋め込んで再生できる（定義が無ければ従来通り既定波形/ROMプリセットのみ）。`@t`/`w`/`y`/`SM`/`SMOF`/`PS`/`SD`/`SDOF`/`SDQR`/`@vr`（リリースエンベロープ）/`@@`（デューティエンベロープ）/`@@r`（リリース音色）/`EN`/`EP`/`MP`/`PT`/`s`（ハードウェアスイープ）もNSF書き出しに対応（`@@`は音色バイトのbit7で固定音色と区別する実機同型のエンコードで、6502側は`DUTY_LOOKUP`が毎フレームデューティを進め既存の`WRITE_VOL_ONLY`（デューティは音量レジスタに同居）で反映する、`@t`/`w`はコンパイル時に音長へ反映済みのため専用オペコード不要、`SD`系はゲートオフとノート差し替えを1つにまとめた複合オペコード`0xE8`で対応（両者は仕様上必ず同フレームになるため、別々のオペコードとして並べると音長0のコマンドが生まれ6502側のカウンタがアンダーフローする）、`@vr`は既存の音量エンベロープ書込み機構(`WRITE_VOL_ONLY`)を再利用するため拡張音源(VRC6/MMC5/FME7/FDS/N163)でも同時に対応、いずれも実機さながらの6502+APUエミュレータでブラウザ再生との完全一致を実測確認済み）。DPCMもNSF書き出しに対応済み（専用バンク配置+DMCトリガールーチン）。`!`/`!!`/`!!!`（データスキップ/シークバー用タイムシフト）と`x`（バイト直接埋め込み、このツールのバイトコードは実機ppmckと非互換のため対応する意味が無い）はNSF書き出しでは意図的に未対応。ループ最適化（繰り返し区間の圧縮、現状は展開済みセグメント列をそのまま書き出す）は未対応。詳細は`ROADMAP.md`フェーズ1.6参照
  - チャンネル割り当て: A=パルス1, B=パルス2, C=三角波, D=ノイズ
  - 出力はチャンネル別・フレーム単位のAPUレジスタ書き込みログ
- `src/mml/player.js` — `MML.Mml.render(source, opt)`：コンパイル結果を6502/NSFを介さず直接APU2A03に適用し、音声波形を生成（`captureSong()`と互換の戻り値）
- `index.html` / `src/main.js` — 「MML作曲」パネルを追加（コンパイル結果表示、キャプチャして再生・シークパネルで試聴）

### Phase 5: 拡張音源対応（VRC6, VRC7, FDS, MMC5, N163, FME-7）

- `src/emulator/expansion/vrc6.js` — `Emu.VRC6Audio`：パルスx2（16段デューティ）+ サウトゥース波（アキュムレータ方式、/14分周）
- `src/emulator/expansion/mmc5.js` — `Emu.MMC5Audio`：パルスx2（2A03パルスと同形式、スイープなし、$5000-5007/$5015）+ハードウェアエンベロープ+$5011 8bit生PCM
- `src/emulator/expansion/fme7.js` — `Emu.FME7Audio`（Sunsoft 5B）：矩形波x3（AY-3-8910形式、$C000アドレスラッチ/$E000データ書き込み）+ノイズ(17bit LFSR)+ハードウェアエンベロープ+5bit対数DAC
- `src/emulator/expansion/fds.js` — `Emu.FDSAudio`：64サンプル6bit波形メモリ音源（$4040-407F波形RAM + $4080/$4082/$4083/$4089制御）
- `src/emulator/expansion/n163.js` — `Emu.N163Audio`：128バイト内部RAMによる波形音源（実機同様のインターリーブレジスタ配置、$F800アドレス/$4800データ）
- `src/emulator/expansion/vrc7.js` — `Emu.VRC7Audio`：emu2413(YM2413/OPLL)を忠実に移植した2オペレータFM音源（16音色テーブル、$9010アドレス/$9030データ）

  - **全6形式で変更が効く(2026-08-26)**: 借用先への載せ替え(音量尺度の写像・音色/波形の作り直し・借用先ごとの音程補正/EN/EP・レター割当・重複検出)を `src/convert/borrow.js`(`MML.Convert.Borrow`)に共通化し、KSS/GBS/HESの変換器がユーザー指定時だけそこを通るようにした
    - **既定の割当のときは各変換器の従来コードをそのまま通る**(=既定の変換結果はバイト単位で不変。共通層は「既定から変えたとき」専用の道)
    - 音量は `volTableFor()` 1本で「対数→線形」「線形→対数」「レンジ違い(0-15↔0-63のFDS/VRC6のこぎり)」を全部まかなう。@vテーブルは抽出時にレジストリを写像プロキシへ差し替えて同じ表で揃える(定数音量とテーブルがズレないように)
    - 音程補正の方針は変換元ごとに保つ(`detuneMode`: KSS/VGM=`detectChorusDetune` / GBS/HES=`applyPitchDetune`、[[kss2mml-pitch-detune-correction]])
    - NSFはネイティブ変換なので「同じ音源の別ch」「2A03パルス↔MMC5パルス(周期式・音量尺度が同一)」「skip」だけに限定(他チップへ移すにはEP/@vが生レジスタ空間で確定する前=抽出前に借用先を決める必要がある)。UIの選択肢もその範囲に絞る

- **SPC再生のフレーム内タイミング再現(2026-08-25)**: SPC再生はキャプチャしたDSP書き込みログを再生する方式だが、1フレーム分の書き込みを**フレーム先頭に一括適用**していたため、AKAO系ドライバのように1フレーム内で多重に制御する曲でKON→KOFFが同一サンプルへ潰れて音が丸ごと消え、GAIN連続書き込みによる減衰も崩れていた
  - 対策: `capture()`/`captureAsync()`が書き込みの**フレーム内サンプル位置(`off`)**を記録し、再生側`_applyWritesUpTo()`が同じ位置で適用する。`off`を持たない旧ログは従来どおり即時適用
  - 実測(FF4 Kingdom Baron): CPU実行の正解に対し音量比 0.720→**1.000**、欠落26フレーム→**0**
  - ★NSF/KSSにも同じ「フレーム先頭一括」構造はあるが、**横展開は退行したため撤回した**(2026-08-25)。NSFは`$4011`直書きスピーチ(水戸黄門)がプチプチノイズ化した。RMS一致だけを根拠に改善と判断したのが誤りで、波形相関で見るとテスト側のシミュレーションが実物の再生経路を再現できていなかった(相関≈0)。横展開する場合は**実物のプレイヤークラスを使った波形比較**で検証すること。GBS/HESはスナップショット方式のため元々対象外

## 実行方法

ビルド不要。`index.html` をブラウザで直接開くだけで動作する（外部依存なし、classic `<script>` 読み込み）。
「▶ 試聴（エミュレータ再生）」でアセンブル→NSF生成→エミュレータ実行→3秒間のAudio再生を行う。
「キャプチャ実行」で指定秒数分を一括レンダーし、トランスポートUIで再生・シーク・早送り・巻き戻しができる。
「MML作曲」パネルでMMLを編集し「MMLコンパイル」で結果を確認、「MMLをキャプチャ」で再生・シークパネルに送って試聴できる。

「拡張音源」セレクトボックスでVRC6/VRC7/FDS/MMC5/N163/FME-7を選択すると、NSF生成時のヘッダフラグおよびMMLコンパイル/再生時の追加チャンネル（E以降）に反映される。
「波形エディタ」でFDS/N163の波形を編集すると、FDS/N163選択時のMMLコンパイル/キャプチャに反映される。
「DPCMコンバータ」で音声ファイルを選択して「変換」すると、DPCMバイナリのダンプが表示され、「プレビュー再生」で復号波形を試聴、「バイナリをダウンロード」でファイル保存できる。

MMLエディタのヘッダにある「?」ボタンで「MMLコマンドヘルプ」が開く。ヘルプの中身は別ファイルではなく
**MML本文そのもの**で、`;@help <コマンド> :: <見出し> :: <カテゴリ>` というコメント行(コンパイルには影響しない)が
付いたブロックを索引化して表示する（`src/mml/helpIndex.js`）。各項目の「▶」でその実演スニペットだけを
その場で鳴らせる（曲中の定義行と当該チャンネルのセットアップ行を自動で足して自己完結MMLに組み立てる）。
表示ソースは「組み込みサンプル / エディタ本文 / 両方」から選べるので、自分のMMLに`;@help`を書けば
自分用の項目がそのまま増える。`node tools/headless/help-lint.js` で、タグの書式・実演スニペットの
